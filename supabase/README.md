# Миграции Supabase

`migrations/001…010` — полный и точный текст всех миграций, применённых к рабочей базе
(выгружено из `supabase_migrations.schema_migrations` 26.09.2026). По ним база поднимается с нуля:
это проверяет GitHub Actions (`.github/workflows/ci.yml`) на каждом push.

| Файл | Что делает |
|---|---|
| 001 | Базовая схема: роли, заказы, документы, RLS, хранилище |
| 002 | Оплата, согласие, владельцы, данные компании, ручная проверка стран |
| 003 | Лимит анкеты 16 КБ, отказ ITIN с причиной |
| 004 | Закрыт вызов триггерных функций через API |
| 005 | Ручная оплата, проверка документов клиента, точное время истории |
| 006 | Заявки партнёров, документы партнёра с видимостью |
| 007 | Видимость файлов в Storage, запись документов |
| 008 | Тип документа партнёра, данные компании, сроки |
| 009 | Два ключа, одобрение компании, закрытие, Operations |
| 010 | Собственный прогресс партнёра, подтверждение клиенту |

Откаты — в `rollback/`, применять строго в обратном порядке (010 → 009 → …).

## Важно

- В рабочей базе версии миграций — метки времени (`20260924234059` и т. д.), в файлах — номера `001…010`.
  **Не запускайте `supabase db push` на рабочую базу** с этими файлами: CLI попытается применить их повторно.
- Новые миграции: сначала файл в `migrations/` через pull request → автопроверка на чистой базе → затем применение
  к рабочей базе. Никаких изменений в рабочей базе в обход репозитория.
- Тестовая база для ручных проверок: проект `taxpasso-staging` (ref `dgkiolejzgefzekunlnn`).
