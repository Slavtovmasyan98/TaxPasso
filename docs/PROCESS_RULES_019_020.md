# Дополнение к PROCESS_RULES.md (миграции 019–020, 28.09.2026)

Вставить в `docs/PROCESS_RULES.md`. Источник: QA_STRESS_TEST_MATRIX.md.

## Деньги

- **Цены продуктов — на сервере** (`product_prices`, меняет админ: `set_product_price`). Цена на сайте и в базе должны совпадать.
- **«Оплачено» = получена полная сумма** = цена продукта + услуги, запрошенные при оформлении. Должная сумма: `order_payment_due(order)`
  (клиент и админ видят одно и то же). Оплата с суммой: `mark_order_paid_manually(order, note, amount)`;
  несовпадение → ошибка «Amount mismatch» (в деталях `expected_cents`).
- Форма без суммы (`mark_order_paid_manually(order, note)`) работает **только пока у заказа нет ожидающих услуг**;
  иначе «Amount required». Интерфейс админа при наличии услуг обязан вызывать форму с суммой.
- Сумма сохраняется в `orders.amount_cents`. Путь Stripe (`mark_order_paid`) сверяет сумму так же и не оплачивает отменённый заказ.
- **Возврат** — только по оплаченному заказу; `scope` соответствует продукту (itin — ITIN-продукты/пакеты, llc — LLC/пакеты);
  без дубля (та же сумма и scope в течение 10 минут); **сумма возвратов не больше оплаченного**.
- **Отмена заказа** отменяет все его услуги (неоплаченные и оплаченные); возврат денег — отдельной записью.
- Оплатить отменённый заказ нельзя ни одним путём.

## Партнёр

- Отменённый заказ партнёр **не видит сразу** и не может добавлять в него документы.
- Завершённый заказ партнёр видит **30 дней** после закрытия (`settings.partner_access_days_after_close`), затем доступ (в т. ч. к файлам) закрывается.
- Причина отмены партнёру не показывается (в ней бывают суммы).
- Сигнал «в работе» (`in_work`) остаётся: партнёр не начинает работу до оплаты, поэтому «передан в работу» неизбежно совпадает с оплатой. Принято как осознанный компромисс.
- Смена партнёра сбрасывает **все** его неподтверждённые предложения: этапы, основание, план специалиста, решения по документам.

## Идемпотентность

- `op_id` привязан к (действие, заказ, пользователь). Тот же `op_id` для другого — ошибка «Operation id reused»;
  честный повтор того же вызова возвращает `already_done`. Интерфейс генерирует **новый** `op_id` на каждое нажатие.

## Анкета

- Пределы: имя ≤ 200, страна ≤ 100, компания ≤ 200, деятельность ≤ 1000 символов; символы `<` и `>` запрещены.
- Контакт консультации: 2–200 символов, без `<`, `>` и управляющих символов; изменение записывается в журнал.
- **Полнота анкеты LLC** (владельцы, доли = 100%, ровно один ответственный, данные компании, паспорт у каждого владельца)
  проверяется при переходе `application → review`. **Переключатель по умолчанию ВЫКЛ**: живой мастер `/app/new` не собирает
  владельцев (все 7 боевых заказов на 28.09 — без владельцев). Включить: админ вызывает `set_order_setup_enforcement(true)`
  **после того, как** единственной точкой входа стал мастер `/app/start`. Действует только на заказы, созданные после включения.
