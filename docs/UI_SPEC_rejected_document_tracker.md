# Доработка: отклонённый документ виден в прогресс-баре заказа

Backend уже всё умеет (миграция 011 + 015), новых миграций не требуется. Это доработка интерфейса
клиентского сайта (`src/pages/Dashboard.tsx`, компонент `OrderTracker` / `StatusTracker`).

## Проблема

Сейчас отклонение документа с причиной видно только в отдельном списке «Документы» на странице заказа.
Клиент может не долистать до него и не понять, почему заказ не двигается.

## Что нужно

В основном прогресс-баре заказа (там же, где «Анкета → Проверка → Подано в штат…») добавить
**красный маркер**, если хотя бы один документ этого заказа отклонён и ещё не заменён.

### Логика (читает существующие поля, ничего не пишет)

```
для заказа o:
  rejected = documents
    .filter(d => d.order_id === o.id && d.superseded_at === null && d.review_status === 'rejected')
  если rejected.length > 0:
    показать красный маркер над/рядом с текущим активным шагом трекера
```

`superseded_at === null` — важно: как только клиент загрузит новую версию (кнопка «Загрузить заново»,
уже реализована), старый документ получает `superseded_at` автоматически (триггер
`handle_document_replacement`), новый документ создаётся с `review_status = 'pending'` по умолчанию.
Значит маркер **исчезает сам**, как только `rejected` пуст — новую миграцию под «стало снова pending»
писать не нужно, это уже так работает.

### Как показать

- Маркер: красная точка/бейдж на текущем активном шаге трекера (`className="pending-el"`,
  как уже используется в остальном интерфейсе) с текстом **«Документ отклонён»**.
- Под маркером — сама причина (`d.review_comment`), например:
  «Паспорт отклонён: фото размыто».
- Клик по маркеру — прокрутка/переход к блоку документов на этой же странице, где уже есть
  кнопка «Загрузить заново» (менять её не нужно, она уже рабочая).
- Если отклонённых документов несколько — показать причину для каждого отдельной строкой.

### Что не трогаем

- Саму логику `review_document` / `propose_document_review` / `confirm_document_review` (015) — без изменений.
- Кнопку и функцию повторной загрузки (`replaceDocument`, уже есть) — без изменений.
- Никаких новых полей в базе не нужно — `review_status`, `review_comment`, `superseded_at`,
  `replaces_document_id` уже всё содержат.

## Проверка после внедрения

1. Партнёр (или админ) отклоняет паспорт клиента с причиной «фото размыто».
2. Клиент открывает заказ → в прогресс-баре красный маркер «Документ отклонён: фото размыто».
3. Клиент нажимает «Загрузить заново», выбирает новый файл.
4. Красный маркер в прогресс-баре сразу исчезает (документ снова `pending`, старый — `superseded`).
5. Партнёр/админ видит новую версию на проверке, как обычно.
