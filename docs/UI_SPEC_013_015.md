# Интерфейс под миграции 013–015

Спецификация для внесения изменений в **Taxpasso Partners** (`src/main.tsx`) и **клиентский сайт**
(`src/pages/Dashboard.tsx`, `src/pages/Services.tsx`, тексты). Правила — в `docs/PROCESS_RULES.md`.

Общие требования:
- Каждое действие, меняющее состояние, передаёт новый ключ операции `p_op: crypto.randomUUID()` (где функция его принимает).
- Ответ `"already_done"` → уведомление «Уже выполнено ранее», без ошибки.
- После любого действия — перезагрузка заказа и связанных данных (как сейчас после `rpc`).
- Не показывать сырые английские ошибки: все новые сообщения базы — в словарь перевода (см. таблицу в конце).

---

## 1. Partners — роль «партнёр»

### 1.1 Загрузка данных — без денег
- Заказы: **только** `sb.rpc("partner_orders")`. Прямой `sb.from("orders")` у партнёра теперь всегда пустой.
- История статусов: отдельно `sb.from("order_status_history").select("*").in("order_id", ids)`.
- Не запрашивать у партнёра: `order_refunds`, `audit_log`, поля оплаты.
- Дополнительно по выбранному заказу: `eligibility_proposals`, `document_review_proposals`, `order_itin`,
  `itin_irs_events`, `order_milestones`, `status_proposals` (как сейчас), `partner_documents`, `documents`, `companies`.

### 1.2 Убрать всё о деньгах
Удалить у партнёра: бейджи «Оплачено / Ожидает оплаты», плашку «Ожидается оплата от клиента»,
отметку «Оплата отмечена вручную», блоки отмены, возвратов, срока пакета, журнал.
Вместо этого — нейтральный бейдж из `in_work`: **«В работе»** / **«Ожидает передачи в работу»**.

### 1.3 Основание ITIN — только предложение
Для ITIN Standard, ITIN + декларация и пакетов, пока `eligibility = pending`
(в пакете — также при `approved`, для предложения отказа):
- Кнопка **«Предложить: основание подтверждено»** → `propose_eligibility(p_order, "approve", null, p_op)`.
- Поле причины + **«Предложить отказ»** → `propose_eligibility(p_order, "reject", reason, p_op)`.
- Если предложение уже есть — показать «Ваше решение отправлено» и сам вариант. Без упоминания проверки админом.
- Прямые `approve_eligibility` / `reject_eligibility` у партнёра **не вызывать**.

### 1.4 Документы клиента — только предложение
У каждого документа клиента (кроме заменённых):
- **«Предложить: принять»** → `propose_document_review(doc, "accepted", null, p_op)`.
- **«Предложить: отклонить»** + причина (обязательна) → `propose_document_review(doc, "rejected", reason, p_op)`.
- Если есть предложение — показать его. Прямой `review_document` у партнёра **не вызывать**.

### 1.5 Этапы «ITIN + подготовка декларации»
Цепочка для `itin_return`: `documents → return_prep → client_signed → caa_interview → sent_irs → itin_received`.
Подписи: `return_prep` — «Подготовка декларации», `client_signed` — «Подписано клиентом».
ITIN Standard и поток ITIN в пакете — без изменений.
Подсказки к шагам:
- `return_prep`: «Подготовить налоговую декларацию (1040-NR или 1040)».
- `client_signed`: «Клиент проверил и подписал декларацию».

### 1.6 Номер ITIN
Для ITIN-заказов и пакетов, начиная с этапа «Отправлено в IRS»: карточка «Номер ITIN»
(поле `9XX-XX-XXXX` + дата присвоения) → `record_itin(p_order, p_itin, p_assigned_on)`. После сохранения — «✓ Сохранено».

### 1.7 Типы документов партнёра
Добавить в выбор: `w7` — «Форма W-7», `coa` — «Certificate of Accuracy (COA)»,
`tax_return` — «Налоговая декларация», `itin_letter` — «Письмо IRS с ITIN (CP565)».

### 1.8 Финальные документы для ITIN
Для ITIN-заказов карточка «Финальные документы»: «Номер ITIN внесён», «Письмо IRS (CP565) отправлено».

### 1.9 События IRS
Показывать (только чтение) список `itin_irs_events`: «Запрос IRS: …», «Отказ IRS: … — повторная подача, попытка N».

## 2. Partners — роль «админ»

### 2.1 Основание ITIN
- Если есть `eligibility_proposals`: показать решение и причину партнёра; кнопки
  **«Подтвердить»** → `confirm_eligibility(p_order, p_op)` и **«Вернуть партнёру»** → `return_eligibility_proposal(p_order)`.
- Всегда доступны прямые **«Одобрить»** → `approve_eligibility` и **«Отклонить»** (+ причина) → `reject_eligibility`.
- **Пакет с отказом** (`bundle_*`, `eligibility = rejected`): плашка «Верните клиенту $100 (доля ITIN)» и кнопка,
  открывающая запись возврата с суммой 100, частью «ITIN» и причиной «Отказ в основании ITIN».

### 2.2 Документы клиента
Если есть `document_review_proposals` для документа — показать предложение партнёра и кнопки
**«Подтвердить»** → `confirm_document_review(doc, p_op)`, **«Вернуть»** → `return_document_review(doc)`.
Прямые «Принять / Отклонить» → `review_document` — остаются.

### 2.3 Номер ITIN
Показать внесённый номер; если не одобрен — **«Одобрить номер»** → `approve_itin(p_order)`.
Админ может внести номер сам (`record_itin`), он сразу одобрен.

### 2.4 IRS
На этапе «Отправлено в IRS» (для ITIN — основной поток, для пакета — поток `itin`):
- **«Запрос IRS»** + текст → `record_irs_event(p_order, stream, "request", note, p_op)`.
- **«Отказ IRS — повторная подача бесплатно»** + текст → `record_irs_event(p_order, stream, "rejection", note, p_op)`,
  с подтверждением: «Поток ITIN вернётся к этапу „Документы“, попытка +1. Оплата не требуется».
- Список событий и «Попытка N» (`itin_attempt`).

### 2.5 Назначение партнёра
Список в «Назначить CAA/CPA» фильтровать по продукту:
`itin_return` — только `CAA/CPA`; `itin_standard`, `bundle_*` — `CAA` и `CAA/CPA`; LLC — все.

### 2.6 Оплата
Кнопка «Отметить оплату» неактивна с пояснением **только для** `itin_standard` / `itin_return` при `eligibility ≠ approved`.
Для пакетов и LLC — активна сразу (сейчас пакеты ошибочно блокируются в интерфейсе).

### 2.7 «Ждёт вашего подтверждения»
Бейдж в списке заказов — также при наличии `eligibility_proposals` или `document_review_proposals`.

## 3. Клиентский сайт

### 3.1 Трекер
Для `itin_return` — цепочка из п. 1.5 с подписями. Если `itin_attempt > 1` — «Повторная подача, попытка N (бесплатно)».

### 3.2 Номер ITIN
Если есть одобренная запись `order_itin` — карточка «Ваш ITIN: 9XX-XX-XXXX» (и дата присвоения).

### 3.3 События IRS
Из `itin_irs_events`:
- запрос — «IRS запросил дополнительные документы: …»;
- отказ — «IRS отказал: …. Готовим повторную подачу бесплатно (попытка N)».

### 3.4 Тексты оплаты
- **Опросник, итог для пакета**: заменить «пакет не оплачивается…» на
  «Пакет оплачивается сразу. Если специалист не подтвердит основание для ITIN, вернём $100, а LLC и EIN оформим как обычно.»
- **Опросник, итог для ITIN**: «Оплата — после того, как специалист Taxpasso подтвердит основание.
  Если IRS откажет, следующая подача — бесплатно. Решение IRS мы гарантировать не можем.»
- **`itinGate`** (ru/en): «ITIN оплачивается после подтверждения основания. Пакеты с ITIN — сразу; если основание
  не подтвердится, вернём $100.»
- **Карточки цен ITIN**: строка «При отказе IRS — повторная подача бесплатно».

### 3.5 Политика возврата (проект)
Переписать под `docs/PROCESS_RULES.md`, раздел «Оплата», оставив пометку «Проект»:
LLC — без возврата после оплаты; пакет — $100 при отказе в основании ITIN; ITIN — оплата после подтверждения
основания, при отказе IRS повторная подача бесплатно; ошибки Taxpasso/партнёра исправляются бесплатно.
Отметить в описании PR: текст требует проверки юристом.

## 4. Новые сообщения базы → перевод

| Сообщение | Партнёр | Админ |
|---|---|---|
| `Not released` | Заказ ещё не передан в работу | Заказ не оплачен |
| `Partner ITIN required` | Внесите номер ITIN | — |
| `Partner ITIN letter required` | Загрузите и отправьте письмо IRS (CP565) | — |
| `ITIN required` | — | Одобрите номер ITIN |
| `ITIN letter required` | — | Передайте клиенту письмо IRS (CP565) |
| `ITIN format must be 9XX-XX-XXXX` | Номер ITIN в формате 9XX-XX-XXXX | то же |
| `Eligibility already decided` | Решение по основанию уже принято | то же |
| `Partner must be CAA/CPA` | — | Для ITIN + декларации нужен партнёр CAA/CPA |
| `Partner must be CAA` | — | Для ITIN нужен партнёр с квалификацией CAA |
| `Not at IRS stage` | — | Действие доступно на этапе «Отправлено в IRS» |
| `Too many attempts` | — | Превышено число попыток подачи |
| `Document replaced` | Документ уже заменён клиентом | то же |
| `No proposal` | — | Предложение уже обработано — обновите страницу |

## 5. Критерии приёмки (проверяются на staging)

1. Партнёр не видит нигде слов «оплата», «оплачено», сумм и возвратов; в сетевых ответах нет денежных полей.
2. Предложение партнёра по основанию ITIN не меняет то, что видит клиент, до подтверждения админа.
3. Предложение партнёра по документу клиента не меняет статус документа у клиента до подтверждения админа.
4. Партнёр не может изменить владельцев / данные компании клиента.
5. Пакет можно отметить оплаченным сразу; ITIN — только после одобрения основания.
6. ITIN + декларация проходит 6 этапов; отказ IRS возвращает к «Документы», попытка 2, без новой оплаты.
7. Финал ITIN невозможен без одобренного номера и опубликованного письма CP565; клиент видит номер после одобрения.
8. При отказе в основании в пакете у админа есть напоминание о возврате $100.
9. Назначение партнёра фильтруется по квалификации.
10. Двойной клик ни на одной новой кнопке не выполняет действие дважды.
